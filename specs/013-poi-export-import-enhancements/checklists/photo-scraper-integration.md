# Photo Scraper Integration Requirements Quality Checklist: 013-poi-export-import-enhancements

**Purpose**: Requirements-quality review checklist ("Unit Tests for Requirements") validating the completeness, clarity, and consistency of Photo Scraper integration, metadata preservation, and import/export round-trip fidelity in Phase 13.  
**Created**: 2026-10-31  
**Feature**: [spec.md](../spec.md) | [plan.md](../plan.md)  

**Review Ownership**: This checklist is a reviewer-owned requirements-quality review artifact. Mark an item `[x]` only when the reviewer determines the requirements-quality criterion is satisfied.  
**Marker Semantics**: `[x]` means the criterion has been reviewed and satisfied for requirements quality. It does NOT mean implementation work is complete.

---

## 1. Schema Mapping & Column Aliasing Quality

- [x] CHK001 - Are the Photo Scraper's canonical export headers (`Photo directory`, `dates visited`, `location_confidence_percent`) explicitly defined in the alias dictionary? [Completeness, Spec §REQ-IMP-002]
- [x] CHK002 - Is the handling of case and separator variations for photo directories (e.g., `photo_dir`, `Photo Directory`, `folder_path`) documented in the canonical alias dictionary? [Clarity, Spec §REQ-IMP-002]
- [x] CHK003 - Is `photo_directory` explicitly designated as an immutable metadata field that is never altered during Phase 1 triage or Phase 2 AI enrichment? [Consistency, Spec §REQ-EXP-006]
- [x] CHK004 - Does the spec define whether `photo_directory` must be preserved in all export formats (CSV, JSON, YAML) even when empty? [Completeness, Spec §REQ-EXP-006]

## 2. Capture Date & Temporal Parsing Requirements Quality

- [x] CHK005 - Are parsing requirements defined for multiple visit timestamps generated by photo scraper runs (e.g., semicolon-separated ISO dates)? [Coverage, Spec §REQ-EXP-006]
- [x] CHK006 - Does the spec define fallback behavior when photo capture dates use legacy EXIF format (`YYYY:MM:DD HH:MM:SS`) instead of standard ISO-8601 (`YYYY-MM-DD`)? [Edge Case, Gap]
- [x] CHK007 - Is the chronological sort order or selection of earliest visit date explicitly specified when merging photo scraper data with existing POIs? [Clarity, Spec §REQ-IMP-007]
- [x] CHK008 - Are format validation criteria for `dates_visited` specified in the pre-import sanity checker to prevent malformed date strings from entering staging? [Completeness, Spec §REQ-IMP-004]

## 3. Location Confidence & Triage Disposition Requirements Quality

- [x] CHK009 - Is the relationship between photo scraper `location_confidence_percent` (0–100) and initial Phase 1 triage disposition quantified with explicit thresholds? [Clarity, Spec §REQ-IMP-004]
- [x] CHK010 - Are requirements defined for how Phase 1 handles photo scraper records flagged with low confidence ($\le 15\%$) or unmappable folder names? [Edge Case, Spec §REQ-IMP-004]
- [x] CHK011 - Does the spec define whether user overrides to coordinates during Phase 1 triage reset or preserve the original `location_confidence_percent`? [Consistency, Gap]
- [x] CHK012 - Can the triage behavior for multi-photo clusters with contradictory coordinate metadata be objectively verified from the requirements? [Measurability, Spec §REQ-IMP-006]

## 4. Lossless Round-Trip Fidelity & Path Integrity

- [x] CHK013 - Are requirements specified to ensure Windows file paths (e.g., `M:\Photos\2010\Japan\`) in `photo_directory` are preserved without backslash-escaping corruption in JSON and YAML exports? [Clarity, Spec §REQ-EXP-002]
- [x] CHK014 - Does the specification clarify how formula injection neutralization handles photo directory paths starting with `@`, `-`, or `+` without corrupting valid filesystem paths? [Edge Case, Spec §REQ-EXP-007]
- [x] CHK015 - Is lossless round-trip re-ingestion of photo scraper metadata (`photo_directory`, earliest capture date, confidence) measured by a specific quantitative success metric? [Acceptance Criteria, Spec §SC-002]
- [x] CHK016 - Does the spec define whether `photo_directory` is exposed in the Explorer table view or reserved for the POI detail drawer? [Coverage, Spec §REQ-AUD-003]

## 5. UI Presentation & Triage Verification Quality

- [x] CHK017 - Are visual display requirements defined for showing the originating `photo_directory` inside the Phase 1 Triage and Phase 2 Review modals? [Completeness, Gap]
- [x] CHK018 - Does the spec specify whether photo directory paths are clickable or strictly rendered as read-only audit text? [Clarity, Gap]
- [x] CHK019 - Are requirements clear on how `dates_visited` extracted from photo EXIF metadata are formatted in the Vistarae Explorer and POI Edit Drawer? [Consistency, Spec §REQ-AUD-003]
- [x] CHK020 - Are requirements defined for selective re-calculation when importing photo scraper records (e.g. keeping photo coordinates and dates while regenerating descriptions via LLM)? [Coverage, Spec §REQ-REC-002]
