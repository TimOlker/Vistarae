## 1. Hybrid PostGIS + pgvector RAG Querying Pipeline

### Context

Travelers need natural language trip planning that transforms fuzzy prompts (e.g. "Scenic coastal hikes and local seafood in Olympic") into structured, spatially coherent daily itineraries. Vistarae already stores points of interest as `geography(Point, 4326)` with composite GiST index `idx_pois_user_geom` and 768-dimensional vector embeddings with HNSW cosine index `idx_pois_embedding`.

### Decision

Implement a unified two-stage query in SQLAlchemy / PostgreSQL:

1. **Spatial Pre-filtering**: Cast user-specified trip bounding box or route corridor to `geography` and evaluate `ST_DWithin(geom, :corridor_geom, :radius_meters)` with strict tenant isolation `user_id = :current_user_id` using the GiST index `idx_pois_user_geom`.
2. **Vector Cosine Ranking**: Order the spatially filtered candidate set by cosine distance `<=>` against the query vector generated by Google Gemini `text-embedding-004` (768 dimensions), limiting results to top $K$ candidates (`ORDER BY embedding <=> :query_vec LIMIT :k`).
3. **LLM Synthesis**: Gemini Flash-Lite / 1.5 Flash (`thinking_budget: 0`) consumes the top $K$ candidate POIs and outputs structured JSON conforming to `ItineraryCreate` Pydantic schema with daily allocations and non-overlapping time slots (08:00–22:00).

```sql
SELECT id, name, address, ST_Y(geom::geometry) AS lat, ST_X(geom::geometry) AS lng,
       estimated_cost, recommended_duration_hours, recommended_visit_days,
       (embedding <=> :query_vec) AS cosine_distance
FROM pois
WHERE user_id = :current_user_id
  AND ST_DWithin(geom, ST_SetSRID(ST_MakePoint(:target_lng, :target_lat), 4326)::geography, :radius_meters)
ORDER BY embedding <=> :query_vec
LIMIT :k;
```

### Rationale

- **Performance & Scalability**: Spatial index evaluation trims thousands of user POIs down to tens within microseconds before vector cosine operations execute.
- **Geographic Reality**: Semantic search alone frequently recommends POIs on opposite sides of a mountain range or across water bodies; spatial pre-filtering guarantees physical accessibility within the trip corridor.
- **Cost & Latency**: Running Gemini Flash-Lite with `thinking_budget: 0` keeps entity extraction and scheduling latency below 3.0 seconds, well within the 15-second Lambda timeout.

### Alternatives Considered

- _Vector-first search without spatial filter_: Querying the nearest semantic neighbors and filtering by distance in Python. Rejected: Incurred high false-positive rates (e.g. recommending a hiking trail 2,000 miles away because it perfectly matched the phrase "coastal hike").
- _Application-level join across separate endpoints_: Querying PostGIS in one query and an external vector database (e.g. Pinecone). Rejected: Violates zero-cost architecture principles and introduces network latency between cloud boundaries.

## 2. Day-by-Day & Hour-by-Hour Itinerary UI & Circuit Breakers

### Context

Travelers need to visually manipulate, adjust, and reorder activities across multiple days. Multi-day POIs (e.g. Disneyland, Yellowstone with `recommended_visit_days = 2` or `3`) must be scheduled logically without overwhelming single days.

### Decision

- **Drag-and-Drop Library**: Standardize on `@hello-pangea/dnd` (the actively maintained, accessible fork of `react-beautiful-dnd`) for the multi-column itinerary board.
- **Daily Over-Planning Circuit Breaker**: Backend and UI enforce a maximum of 10.0 hours of active exploration per day. Active duration is calculated as $\sum \text{duration\_hours} + \sum \text{transit\_hours}$. If scheduled activities exceed 10.0 hours on any day, an amber warning banner appears, preventing auto-generation or warning the user during manual drag-and-drop.
- **Multi-Day POI Allocation**:
  - When $\ge N$ days are available in the trip, the engine partitions the POI into $N$ consecutive daily highlight blocks (e.g., "Day 1: Lower Loop", "Day 2: Upper Loop"), allocating balanced exploration segments.
  - When remaining available days in the itinerary are fewer than `recommended_visit_days`, the engine rejects silent truncation and prompts the user with an actionable dialog: _"Not enough days available for full visit (requires N days). Please extend the trip duration or remove scheduled events to make room."_
- **Missing Meal Detection**: Checks for unallocated intervals during lunch (11:30–14:00) and dinner (17:30–20:30). If no restaurant or meal activity is present, an advisory card suggests saved restaurants within 1,500m or prompts packing a lunch.
- **PDF Export Engine**: Employs `@media print` CSS rules, stripping interactive navigation bars, expanding all day accordions, and triggering native browser `window.print()` / save-as-PDF.

### Rationale

- **Zero Heavy Lambda Dependencies**: Eliminates the need for running server-side Headless Chrome (Puppeteer) in Lambda, which would blow through deployment package limits and invoke high cold start costs.
- **High-Fidelity Interaction**: `@hello-pangea/dnd` delivers 60fps drag operations, accessible keyboard movement, and immediate visual feedback without layout thrashing.

### Alternatives Considered

- _Silent visit truncation for multi-day POIs_: Scheduling only 1 day of a 3-day park. Rejected: Creates traveler confusion and leads to under-planning major attractions.
- _Server-side WeasyPrint or Playwright PDF generator_: Rejected: Adds 150MB+ binary dependencies to Lambda and exceeds the 250MB uncompressed limit, violating Constitution Principle 2.

## 3. AWS SAM Edge Topology & Single-Page Application (SPA) Routing

### Context

Vistarae frontend is a static Single-Page Application (Vite + React + TypeScript) that uses client-side routing (e.g. `/trips`, `/trips/:id`, `/settings`). When deployed to a private S3 bucket fronted by CloudFront with Origin Access Control (OAC), direct requests to `/trips/123` result in S3 returning `403 Access Denied` or `404 NoSuchKey` because the S3 key `/trips/123` does not exist on disk.

### Decision

Deploy an ultra-lightweight **CloudFront Function** (`spa-router.js`) associated with the CloudFront distribution's default cache behavior on `viewer-request`:

```javascript
function handler(event) {
  var request = event.request;
  var uri = request.uri;

  // Check whether the URI is missing a file extension and is not an API route
  if (!uri.includes(".") && !uri.startsWith("/api/")) {
    request.uri = "/index.html";
  }
  return request;
}
```

- **Origin Access Control (OAC)**: Configured using `AWS::CloudFront::OriginAccessControl` targeting the private S3 bucket.
- **S3 Bucket Policy**: Strictly grants `s3:GetObject` to `cloudfront.amazonaws.com` conditioned on `AWS:SourceArn` matching the CloudFront distribution ARN.
- **API Cache Behavior (`/api/*`)**:
  - Origin: API Gateway HTTP API (`{api-id}.execute-api.us-east-2.amazonaws.com`).
  - Cache Policy: Managed `CachingDisabled` (`4135ea2d-6df8-44a3-9df3-4b5a84be39ad`).
  - Origin Request Policy: Managed `AllViewerExceptHostHeader` (`b689b0a8-53d0-40ab-baf2-68738e2966ac`).
  - Allowed Methods: `GET, HEAD, OPTIONS, PUT, POST, PATCH, DELETE`.

### Rationale

- **Zero Cold Starts**: CloudFront Functions run in V8 isolates across 450+ CloudFront edge locations with sub-millisecond execution overhead.
- **Zero Cost**: AWS Free Tier includes 2,000,000 CloudFront Function invocations per month.
- **Security & Integrity**: Preserves true HTTP 404 responses for real missing assets (e.g., `/assets/missing-chunk.js` returns 404, not `index.html`).

### Alternatives Considered

- _CloudFront Custom Error Response (404 -> /index.html with status 200)_: Rejected: Masked all real missing asset errors as 200 OK, causing silent script execution failures in Vite.
- _Lambda@Edge_: Rejected: Costs $0.60/million requests, incurs 50–200ms cold starts, and cannot be modified without global propagation delays.

## 4. SpendKillSwitch Fallback at Account-Level Concurrency Reserve Floor

### Context

AWS Budgets monitors billing and emits an SNS alert when spending crosses $15.00. The standard kill switch mechanism sets Lambda `ReservedConcurrentExecutions: 0` to immediately stop all invocations. However, AWS Lambda strictly enforces an account-level **Unreserved Execution Concurrency Floor** (typically 100 or 10 in low-quota/new accounts). If setting `ReservedConcurrentExecutions: 0` would breach this floor, AWS raises `ValidationException`, preventing the concurrency update from executing.

### Decision

Implement an infallible **4-tier cascading shutdown** in `SpendKillSwitch` Lambda:

1. **Tier 1 — API Gateway Stage Throttling (Immediate Edge Cutoff)**:
   Invoke `apigatewayv2:UpdateStage` to set the `$default` stage throttle limits to `RateLimit: 0` and `BurstLimit: 0`. This drops 100% of incoming edge HTTP traffic at API Gateway without invoking any Lambda compute, completely bypassing Lambda concurrency limits.
2. **Tier 2 — SQS Event Source Mapping Disablement**:
   Invoke `lambda:UpdateEventSourceMapping` to set `Enabled: false` on the SQS mapping for `BatchIngestWorker`. This immediately stops polling the `vistarae-ingest` queue.
3. **Tier 3 — Neon Database & Middleware State Lock**:
   Execute `UPDATE system_settings SET killswitch_active = true, updated_at = NOW();` via direct connection. FastAPI `RateLimitMiddleware` checks this state and returns RFC 7807 503 Service Unavailable for any in-flight requests.
4. **Tier 4 — Best-Effort Lambda Concurrency Reservation**:
   Attempt to set `ReservedConcurrentExecutions: 0` across domain Lambdas (`PoiFunction`, `UserFunction`, `IngestFunction`, `AdminFunction`, `BatchIngestWorker`). Wrap each call in a `try...except ClientError` block that catches `ValidationException` (or `ResourceConflictException`) and logs a warning to `sys.stderr` without halting the shutdown pipeline.

An administrative restoration script (`scripts/reset_killswitch.py`) reverses these 4 tiers upon manual confirmation.

### Rationale

- **Guaranteed Spend Containment**: API Gateway stage throttling is 100% independent of Lambda account quotas and stops edge billing immediately.
- **Graceful Error Handling**: The script does not crash or exit prematurely if an account limit is encountered.

### Alternatives Considered

- _Deleting the CloudFormation Stack via boto3_: Rejected: Destroys user data, SQS queues, and CloudFront distributions, requiring hours of recovery.
- _Setting Lambda memory to 128MB_: Rejected: Does not prevent invocations from occurring and incurring costs.

## 5. CloudFront SNI Host Header Routing & CORS Delegation

### Context

API Gateway HTTP API default endpoints (`{api-id}.execute-api.us-east-2.amazonaws.com`) mandate that the HTTP `Host` header match the execute-api domain name to resolve TLS Server Name Indication (SNI) and route internally. If CloudFront forwards the viewer's `Host` header (`*.cloudfront.net`), API Gateway rejects the request with HTTP `403 Forbidden` (`{"message":"Forbidden"}`).
Furthermore, if API Gateway's SAM definition declares built-in `CorsConfiguration`, API Gateway attaches CORS headers. If backend FastAPI also attaches `CORSMiddleware` headers, CloudFront returns duplicate `Access-Control-Allow-Origin` headers, breaking browser security.

### Decision

1. **Managed Origin Request Policy**: Attach `AllViewerExceptHostHeader` (`b689b0a8-53d0-40ab-baf2-68738e2966ac`) to CloudFront's `/api/*` cache behavior. This substitutes the `Host` header with `{api-id}.execute-api.us-east-2.amazonaws.com` while forwarding all viewer headers: `Origin`, `Authorization`, `Idempotency-Key`, `traceparent`, `X-Amzn-Trace-Id`, `X-Forwarded-For`, and `CloudFront-Forwarded-Proto`.
2. **Authoritative CORS Delegation**: In `template.yaml`, the `AWS::Serverless::HttpApi` resource explicitly omits `CorsConfiguration`. CORS is delegated 100% to FastAPI's Starlette `CORSMiddleware`, which validates the forwarded `Origin` header against `https://*.cloudfront.net` (production) and `http://localhost:5173` (local).

### Rationale

- Completely eliminates CloudFront `403 Forbidden` SNI errors.
- Prevents duplicate CORS header collisions.
- Fully adheres to Constitution Principle 6.

### Alternatives Considered

- _Custom ACM Domain on API Gateway_: Adding `api.vistarae.com`. Rejected: Incurs additional Route53 hosted zone management and complex certificate validation outside the free tier.
- _Lambda@Edge Origin Request Hook_: Overriding `request.headers['host']`. Rejected: Unnecessary complexity when CloudFront provides a native managed policy.

## 6. Keyless GitHub Actions OIDC CI/CD Pipeline

### Context

Deploying from CI/CD traditionally requires storing static `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` in GitHub repository secrets. Long-lived credentials present severe security risks if leaked and violate modern cloud security posture.

### Decision

- **Keyless OIDC Identity Provider**: Configure an IAM OpenID Connect identity provider in AWS for `token.actions.githubusercontent.com`.
- **IAM Role `GitHubActionsDeployerRole`**: Scoped trust policy with condition:
  `"StringLike": { "token.actions.githubusercontent.com:sub": "repo:timolker/vistarae:*" }`
  and `"StringEquals": { "token.actions.githubusercontent.com:aud": "sts.amazonaws.com" }`.
- **Monorepo Path-Filtered Workflows**:
  - `ci.yml`: Triggers on pull requests affecting `services/**`, `packages/core/**`, `frontend/**`, `template.yaml`, or `db/migrations/**`. Runs `ruff`, `pytest --cov=src --cov-fail-under=90` with Docker PostGIS, `alembic check`, OpenAPI drift check (`git diff --exit-code ./frontend/src/types/api.ts`), and `sam validate --lint`.
  - `deploy.yml`: Triggers on push to `main`. Assumes `GitHubActionsDeployerRole` via OIDC, executes `alembic upgrade head` over direct Neon SSL (`?sslmode=require`), synchronizes S3 assets with immutable cache headers, invalidates CloudFront (`/index.html`, `/`), and performs a single `/health/ready` check.

### Rationale

- Zero stored static AWS credentials in GitHub.
- Credentials expire automatically after each job execution.
- Least-privilege IAM policy restricts deployment strictly to the Vistarae CloudFormation stack and S3 bucket.

### Alternatives Considered

- _Deploying via SSH to a Bastion VM_: Incurs running compute costs and violates serverless architecture.
- _Pushing via AWS IAM User with Rotated Keys_: Still creates permanent credentials susceptible to exfiltration.
